# 前端工程治理与演进路线

更新时间：2026-08-03

## 目的

本文档记录 `workflow-agent-web` 当前的工程成熟度、潜在风险、长期约束和下一步整改顺序。后续页面、工作流能力和 Agent 功能必须在不破坏本文档约束的前提下演进。

项目当前已经具备统一请求层、租户化查询缓存、路由权限、功能目录、设计系统、单元测试和 Playwright 测试，能够支持内部试用。生产就绪仍取决于身份安全、真实前后端集成、契约治理、可访问性和大文件拆分。

## 不可破坏的工程约束

### 功能边界

1. 页面和业务组件必须归属明确的 `features/<domain>`，不得把业务逻辑放回全局组件或 `App.vue`。
2. 每个 feature 应逐步建立公开入口；跨 feature 只能依赖公开类型、组件或用例，不得任意引用对方内部文件。
3. View 只负责页面编排。复杂状态、请求组合、表单规则和 BPMN 操作必须下沉到 composable、领域函数或独立组件。
4. 通用组件只能包含稳定的视觉和交互语义，不得携带特定业务接口调用。

### API、状态和租户

1. 所有 HTTP 请求必须经过统一 `apiClient`；不得在页面中直接创建 Axios/Fetch 客户端。
2. 所有租户敏感的服务端状态必须使用包含 `tenantCode` 的 Query Key。
3. 切换租户时必须清理或隔离旧租户缓存、临时表单、选人结果和 BPMN 编辑状态。
4. Pinia 只保存真正的客户端会话或跨页面 UI 状态；服务端状态由 TanStack Query 管理。
5. 接口模型必须由 OpenAPI 契约生成或校验；不得长期依赖前后端手工维护同名类型。

### 设计系统与交互

1. 颜色、间距、圆角、阴影、字号和控件高度必须来自设计 Token 或统一组件，不得在页面重复定义近似值。
2. 同一语义的按钮、状态标签、筛选栏、分页器、弹窗和表单字段必须使用同一组件和布局模式。
3. 原生可访问语义优先；图标按钮必须有名称，键盘焦点必须可见，弹窗必须正确管理焦点。
4. 选人和流程配置不得暴露 Flowable 表达式、内部变量名或后端实现细节。
5. 大数据选择器必须使用服务端搜索、分页和防抖，不能一次加载全部用户。

### 安全

1. 浏览器不得存储服务端服务客户端密钥，也不得生成 `X-Workflow-Token`。
2. 页面权限只用于用户体验；后端权限校验始终是最终安全边界。
3. 未经安全评审不得使用 `v-html`、动态脚本、未净化 SVG/HTML 或把 Token 输出到日志。
4. 生产身份方案完成后，应优先使用安全 Cookie 或受保护的会话机制，避免长期把访问 Token 保存在 `localStorage`。

## 分阶段路线

### 阶段 A：质量和安全闭环

1. 增加前端 CI 和统一 `verify` 命令。
2. 建立真实后端 E2E 环境和最小关键路径。
3. 与后端共同建立 OpenAPI 契约、错误码和 Trace ID。
4. 设计并迁移安全会话存储方案，增加 CSP 和安全头验证。

### 阶段 B：可维护性治理

1. 拆分 `ProcessDesignerView`、`AssignmentRuleListView`、实例详情和超大样式文件。
2. 建立 feature 公共 API、依赖检查和共享组件目录准入规则。
3. 将状态标签、筛选区、表单布局、用户搜索和流程版本展示收敛为统一组件。
4. 加入包体预算、可访问性测试和关键视觉回归测试。

### 阶段 C：工作流与 Agent 体验

1. 在后端完成任务中心、组织、表单、通知和 SLA 后再增加对应前端域。
2. Agent 页面只展示受治理的定义、运行、步骤、检查点、工具授权和人工确认，不暴露原始密钥。
3. Agent 长任务必须使用可恢复的服务端状态和事件刷新，不能依赖页面轮询保存真实执行状态。
4. 看板、Agent 编排和 BPMN 设计器应复用统一身份、租户、权限、审计和设计系统。

## 变更完成标准

后续任何非文档变更至少必须满足：

- 所属 feature、状态归属和跨域依赖明确。
- 租户切换、权限变化、401、网络失败和空数据状态得到处理。
- 新交互具有加载、成功、失败、禁用、防重复提交和键盘操作状态。
- 同类控件复用设计 Token 和共享组件，不新增随意覆盖样式。
- 新业务规则有单元测试；关键用户路径有 Playwright 测试。
- `pnpm check` 通过；发布前执行完整 E2E，不得通过关闭 lint 或类型规则规避失败。
- API 变化同步更新契约、转换模型、Query Key 和缓存失效策略。
- 大型功能先更新本治理文档或架构决策，再开始实现。
